# 2026-10-21 工创赛工作日志与交接说明

## 项目目标与当前状态

目标是在 LXB407VE-P1 核心板（STM32F407VET6）上，通过板载 Type-C 的 USB CDC 虚拟串口接收电脑实时发送的视频帧，并显示到 1.54 寸 240×240 ST7789 SPI 屏幕。目前完成硬件链路核对、两个厂商示例工程分析、Keil 构建/下载问题排查和首版通信协议设计；**视频发送程序及接收显示固件尚未实现，8 fps 尚未实测**。不要把协议设计误认为已在板上跑通。

本次约定的完整协议见 [`../user_doc/usb_cdc_video_protocol_v0.1.md`](../user_doc/usb_cdc_video_protocol_v0.1.md)。

## 今天确定的技术路线

电脑端解码 MP4 或摄像头图像，裁切/缩放到 240×240，将 RGB888 像素量化成 1 字节 RGB332，按行排列。每帧 USB 载荷 57,600 字节；目标 8 fps 时约 460,800 字节/秒，仅为设计预算。STM32 收齐并校验整帧，再转成 RGB565；LCD 每帧接收 115,200 字节。建议用 16 行、7,680 字节的 RGB565 条带缓冲区，逐条带调用 `LCD_SetAddress` 和 `LCD_WriteBuff`。协议采用停止等待：整帧写屏完成后板才回 ACK，电脑再发送下一帧。电脑跳过过期的视频源帧，避免积累延迟。

USB CDC 回调边界不等于协议包边界。接收回调应快速复制收到的字节并重新使能接收；解析、CRC 和屏幕写入放在主循环或任务中，不应在 USB 回调里长时间阻塞。屏幕示例与 USB 示例分别采用标准外设库和 HAL，不能直接拼接两个 `main.c`。建议以 HAL USB CDC 工程为基底，移植 LCD 需要的 SPI/GPIO 初始化及写屏逻辑，先完成静态测试图再接入视频协议。

## 下一位接手者的实施顺序

1. 获取上述核心板原理图和两个示例工程；核对屏幕排线、供电、SWD/J-Link 接线及 Keil 目标设备。先在 Keil 独立构建/运行静态屏幕测试，记录实机结果。
2. 复制 HAL USB CDC 参考工程为新工程；仅在新工程内移植 ST7789 驱动，显示纯色和 240×240 彩条，验证坐标方向与 RGB565 字节顺序。
3. 按协议文档实现 `START`、`FRAME`、CRC、序号、超时及 ACK/NACK。为 57,600 字节输入帧和 16 行输出条带分配内存；确认 Keil RAM 区域与实际分配一致。先用协议文档中的全黑测试向量验收。
4. 编写电脑端发送器：读取视频或摄像头帧、缩放/裁切、RGB332 量化、封包、串口写满、等待应答、丢弃过期帧。再依次测纯色、彩条、移动图像，记录 USB 吞吐、屏幕耗时、实际帧率和延迟。
5. 若帧率不达标，先测量 USB 接收与 SPI 刷屏各阶段时间，再决定是否优化 USB 缓冲、SPI/DMA 或画面编码；目前没有证据保证 8 fps。
